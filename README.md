# STM32F103RB Bare-Metal Servo Control via PWM + USART

> Bare-metal PWM servo control on NUCLEO-F103RB. No HAL, no libraries. Every register configured directly from RM0008. Servo angle controlled via serial terminal input.

---

## Project Overview

This project controls an SG90 servo motor using PWM generated by TIM3 on the STM32F103RBT6. The user types an angle (0–180°) into a serial terminal, the STM32 parses it, maps it to a PWM pulse width, and the servo moves to that position. An Arduino UNO was used as a logic analyzer to verify the PWM signal independently.

## PWM Configuration

```
Timer clock  = 72MHz (APB1 timer clock after doubling rule)
PSC          = 71    → 72MHz / 72 = 1MHz → 1 tick = 1μs
ARR          = 19999 → 20000 ticks = 20ms = 50Hz

SERVO_MIN    = 500   → 0.5ms → 0°
SERVO_MID    = 1500  → 1.5ms → 90°
SERVO_MAX    = 2500  → 2.5ms → 180°

Duty cycle formula:
CCR1 = SERVO_MIN + (angle × (SERVO_MAX - SERVO_MIN)) / 180
```

### Verified Output (Arduino UNO pulseIn measurement)

```

Period    : ~19856μs (target 20000μs)           ✅
Pulse @ 90°: ~1492μs (target 1500μs, error 8μs) ✅
Pulse @ 0° : ~500μs  (target 500μs)             ✅
```

## Register Map

### TIM3 (Base: 0x40000400)

| Register | Offset | Purpose |
|---|---|---|
| TIM3_CR1 | 0x00 | Counter enable (CEN bit 0) |
| TIM3_EGR | 0x14 | Update event generation (UG bit 0) |
| TIM3_CCMR1 | 0x18 | PWM mode selection (OC1M bits 6:4) |
| TIM3_CCER | 0x20 | Channel output enable (CC1E bit 0) |
| TIM3_PSC | 0x28 | Prescaler |
| TIM3_ARR | 0x2C | Auto-reload (period) |
| TIM3_CCR1 | 0x34 | Capture/Compare (pulse width) |

### PA6 GPIO Configuration

```
Pin 6 → bits 27:24 of GPIOA_CRL
CNF = 10 (AF push-pull)
MODE = 11 (50MHz output)
4-bit value = 1011 = 0xB
```

## Problems Encountered and Solutions

---

### Problem 1 — PA5 Has No Timer Alternate Function on DS5319

**What happened:**
Initial plan was to use PA5 (onboard LD2 LED) for PWM. When checking DS5319 pin table, PA5 alternate functions showed only SPI1_NSS and ADC12_IN5 — no timer channel.

**Investigation:**
PWM output requires a timer channel physically routed to that pin in silicon. PA5 has no timer channel. This is a hardware routing constraint — no register configuration can change it.

**Solution:**
Switched to PA6 which has TIM3_CH1 listed as alternate function in DS5319. External LED or servo connected to PA6 instead of using onboard LD2.

**Lesson:**
Always check the pin alternate function table in the datasheet before choosing a PWM pin. The silicon routing is fixed.

---

### Problem 2 — Shadow Registers and Missing Update Event (EGR)

**What happened:**
TIM3 configured correctly — PSC, ARR, CCMR1, CCER all set. Arduino UNO reported "No pulse detected" on PA6. Servo did not move. No output at all despite all register values appearing correct in SFR panel.

**Investigation:**
STM32 timers use **shadow registers** — a double-buffering mechanism. Values written to PSC, ARR, and CCR1 do not immediately become active. They sit in preload registers until an **update event** forces them into the active registers that the counter hardware actually uses.

From RM0008 TIMx_EGR register description:
> UG bit: Setting this bit re-initializes the counter and generates an update of the registers.

Without triggering this update event, CCR1 remained at its reset value of 0 — giving a pulse width of 0μs — invisible to any measurement tool.

Additionally, OC1PE (preload enable for CCR1) was set to 1 in CCMR1. When OC1PE=1, CCR1 itself is also shadowed and requires an update event to become active. This compounded the problem.

**Solution:**
```c
// Set all values first
TIM3_CCMR1 |= (0x6 << 4);   // PWM mode 1
TIM3_CCMR1 |= (0x1 << 3);   // OC1PE = 1
TIM3_CCER  |= (1 << 0);      // CC1E = 1
TIM3_CCR1   = 1500;           // initial pulse width

// THEN trigger update event to load all values
TIM3_EGR   |= (1 << 0);      // UG bit

// THEN enable counter
TIM3_CR1   |= (1 << 0);      // CEN = 1
```

**Lesson:**
Always trigger the update event (EGR UG bit) after configuring TIM3 registers and before enabling the counter. The order is: configure → EGR → enable. This is one of the most common bare-metal timer bugs.

---

### Problem 3 — TIM3_EGR Used Without Being Defined

**What happened:**
`TIM3_EGR |= (1 << 0)` was written in the init function but `TIM3_EGR` was never added to the register defines at the top of the file. This caused either a compile error or undefined behavior depending on compiler handling.

**Solution:**
```c
#define TIM3_EGR  (*(volatile uint32_t *)(TIM3_BASE + 0x14))
```

**Lesson:**
Every register used must be explicitly defined. The compiler does not know about hardware registers automatically — they are just memory addresses. An undefined register silently writes to address 0x00000000 (interrupt vector table) which corrupts the startup sequence.

---

### Problem 4 — USART Serial Communication Lost After Adding TIM3

**What happened:**
Serial communication worked before adding PWM code. After adding `tim3_pwm_init()`, the Nucleo serial monitor went completely silent — no output at all.

**Investigation:**
Both USART2 (PA2, PA3) and TIM3_CH1 (PA6) use GPIOA pins. All eight Port A pins 0-7 share a single register — GPIOA_CRL. When `tim3_pwm_init()` ran before `usart2_init()`, the initialization sequence was:

```
tim3_pwm_init() runs first
  → enables GPIOA clock
  → writes to GPIOA_CRL bits 27:24 (PA6)

usart2_init() runs second
  → writes to GPIOA_CRL bits 11:8 (PA2) and 15:12 (PA3)
```

This should have been safe since different bit ranges were touched. However, the missing TIM3_EGR define (Problem 3) was causing undefined behavior that corrupted the entire initialization sequence, making USART appear broken.

**Solution:**
Two fixes together resolved this:
1. Define TIM3_EGR correctly
2. Call `usart2_init()` before `tim3_pwm_init()` as defensive ordering

```c
int main(void) {
    pll_init();
    systick_init();
    usart2_init();      // USART first — PA2/PA3 stable
    tim3_pwm_init();    // PWM second — only touches PA6
}
```

**Lesson:**
When multiple peripherals share the same GPIO port, initialize them in a deliberate order. Always use `&=` and `|=` (read-modify-write) never `=` when writing to shared GPIO registers. One `=` on GPIOA_CRL destroys configuration for all 8 pins simultaneously.

---

### Problem 5 — Arduino pulseIn() Returning Zero

**What happened:**
Used Arduino UNO as a logic analyzer with `pulseIn(8, HIGH, 25000)`. Consistently returned 0 even after PWM was confirmed working (servo was moving).

**Investigation:**
`pulseIn()` waits for a pulse to START within the timeout window. The SG90 servo PWM pulse is only 500–2500μs wide inside a 20000μs period — only 2.5–12.5% of the period is HIGH. `pulseIn` was frequently being called during the LOW portion of the cycle (87.5–97.5% of the time) and timing out before seeing a rising edge.

**Solution:**
Increase timeout to 100000μs (100ms) to guarantee catching at least one complete cycle:

```cpp
unsigned long high_time = pulseIn(8, HIGH, 100000);
```

**Lesson:**
`pulseIn()` timeout must be significantly larger than the PWM period, not just the pulse width. For narrow duty cycles (servo PWM), the timeout needs to cover multiple periods to reliably catch a pulse.

---

### Problem 6 — CCMR1 Second Write Overwriting First

**What happened:**
In early code version:
```c
TIM3_CCMR1 = (0x6 << 4);   // sets OC1M
TIM3_CCMR1 = (0x1 << 3);   // intended to set OC1PE, actually overwrites OC1M
```

Using `=` instead of `|=` on the second write completely erased the first write.

**Solution:**
```c
TIM3_CCMR1 |= (0x6 << 4);   // OC1M = 110
TIM3_CCMR1 |= (0x1 << 3);   // OC1PE = 1 (preserved OC1M)
```

**Lesson:**
Never use `=` for register bit-setting operations unless you intend to write the complete register value from scratch. Always use `|=` to set bits and `&= ~()` to clear bits.

---

### Problem 7 — APB1 Timer Clock Doubling Rule

**What happened:**
TIM3 is on APB1. APB1 clock was set to 36MHz (half of 72MHz due to mandatory /2 prescaler). Initial PSC calculation used 36MHz as timer clock, giving wrong frequency.

**Investigation:**
RM0008 clock tree section states:
> "If the APB prescaler is not 1, the timer clock frequency is doubled."

Since APB1 prescaler = /2 (not 1), TIM3 actually receives:
```
Timer clock = APB1 clock × 2 = 36MHz × 2 = 72MHz
```

**Solution:**
```
PSC = (72MHz / 1MHz) - 1 = 71   (not 35)
```

**Lesson:**
Timers on APB1 do NOT run at the same frequency as other APB1 peripherals when the APB1 prescaler is not 1. This doubling rule is in the RCC clock tree section of RM0008 and applies to all timers. Always verify timer clock frequency against the clock tree, not just the APB clock.

---

### Problem 8 — Servo Position Inaccurate (Old Hardware)

**What happened:**
Servo moved to different positions for different angles but positions were not accurate. Servo wobbled for 1-2 seconds before settling. This persisted even with correct PWM signal verified by Arduino.

**Investigation:**
The SG90 servo had been unused since approximately 8th standard (4-5 years). SG90 uses an internal potentiometer for position feedback. The pot had likely degraded — causing noisy position feedback, hunting behavior, and inaccurate positioning.

The standard 1ms-2ms pulse range was also too narrow. SG90's actual mechanical range extends from approximately 0.5ms to 2.5ms.

**Solution:**
```c
#define SERVO_MIN  500    // 0.5ms actual SG90 minimum
#define SERVO_MAX  2500   // 2.5ms actual SG90 maximum
```

**Lesson:**
Servo calibration values (MIN/MAX pulse widths) vary between manufacturers and even between units of the same model. Always calibrate by finding the actual end-stop pulse widths for your specific servo. Old or worn servos may not perform to datasheet specifications regardless of correct PWM configuration.

## Boot Sequence

```
Power on
    ↓
startup_stm32f103rbtx.s → SystemInit() (empty) → main()
    ↓
pll_init()      → 72MHz SYSCLK via HSE + PLL×9
systick_init()  → 1ms interrupt tick
usart2_init()   → PA2/PA3, 115200 baud, RXNE interrupt
tim3_pwm_init() → PA6, TIM3 CH1, 50Hz PWM
    ↓
Serial prompt: "Enter angle (0-180) and press Enter"
    ↓
User types "90\r\n"
    ↓
USART2_IRQHandler() → accumulates chars → sets rx_complete on '\r'
    ↓
main() → str_to_int("90") → 90
    ↓
servo_set_angle(90) → CCR1 = 500 + (90×2000)/180 = 1500
    ↓
TIM3 hardware generates 1.5ms pulse every 20ms
    ↓
SG90 moves to 90°
```
